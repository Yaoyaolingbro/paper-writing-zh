# 中文 AI 论文写作

## 概述

这个 skill 是一个中文优先的 AI/ML 会议论文写作流程总控器。用户通常会在一个新的论文模板目录中启动它。讨论性的产物可以用 Markdown 输出；真正进入论文正文时，应直接修改 LaTeX 文件。

整个流程必须保持交互式，并且受事实约束。在确定故事线之前先提问；不确定的内容必须标为 TODO；绝不能编造实验结果、数据集、baseline、数值、消融实验或论文主张。

## 阶段路由

根据用户请求和当前文件判断应进入哪个阶段：

1. **研究访谈与故事线建立**：读取 `references/interview.md` 和 `references/storyline.md`。
2. **摘要草稿**：使用 `abstract-writing/SKILL.md`。
3. **大纲与段落计划**：使用 `outline-writing/SKILL.md`。
4. **LaTeX 中文注释骨架**：使用 `latex-comment-drafting/SKILL.md`。
5. **中文扩写**：使用 `chinese-expansion/SKILL.md`。
6. **学术英文翻译**：使用 `academic-translation/SKILL.md`。
7. **审阅或缺口分析**：读取 `references/revision-checklists.md` 和 `references/fact-todo-policy.md`。

除非用户明确说明中文大纲和内容已经足够定稿，否则不要直接跳到英文翻译。

## 默认流程

1. 用短轮次访谈用户，通常每轮提出 3-6 个高价值问题。
2. 区分已确认事实、合理推断和缺失信息。
3. 起草初版摘要，把它作为暂时的故事线契约。
4. 讨论缺失实验、不清楚的主张、薄弱比较和潜在审稿人质疑。
5. 用 Markdown 输出章节级和段落级计划。
6. 在 LaTeX 文件中为每个章节和段落写中文 `%` 注释。
7. 把中文注释扩写为更完整的中文写作笔记，同时保留摘要和 TODO。
8. 只把用户确认过的中文内容翻译成学术英文。
9. 最后检查摘要、引言、方法、实验、局限和主张之间是否一致。

## 必须遵守的行为

- 保留用户原始主张和不确定程度。
- 对缺失事实、不完整实验、未确认数值和不确定术语使用 `[TODO: ...]`。
- 修改 LaTeX 时优先写注释；不要静默替换用户已有的大段正文。
- 在后续阶段持续保留摘要，让全文始终围绕同一个故事线展开。
- 如果实验不足，要直接讨论并提出具体补充建议，但不能把建议中的实验写成已经完成。

## 常见输出

- 如果项目中已有或需要写作笔记目录，可以用 `writing-notes/*.md` 保存访谈、故事线、大纲和审阅笔记。
- LaTeX 修改应落在现有论文文件中，例如 `main.tex`、`sections/*.tex` 或会议模板对应的文件。
- 当信息缺失时，在 Markdown 和 LaTeX 中都使用 TODO 标记。
