# 事实与 TODO 规则

这个写作流程必须受证据约束。Codex 不能编造论文事实。

## 内容类别

- **已确认事实**：用户明确提供，或文件中已经存在。
- **合理推断**：由已确认事实推出，但没有被直接说明。讨论时必须标明这是推断。
- **缺失事实**：写作需要但当前未知。必须标为 `[TODO: ...]`。
- **拟补充实验**：用于增强论文的未来实验建议。绝不能写成已经完成。

## 绝不能编造

不要编造：

- 数据集名称
- benchmark 名称
- baseline 名称
- 数值结果
- 排名或 state-of-the-art 主张
- p-value、置信区间或统计检验
- 引用
- 模型规模、训练预算、硬件或运行时间
- 用户研究细节
- 与已知事实矛盾的局限

## 必须使用的 TODO 风格

TODO 要具体：

- `[TODO: 确认数据集名称]`
- `[TODO: 从 Table 1 补充主要比较数值]`
- `[TODO: 补充最强 retrieval-augmented generation baseline 的引用]`
- `[TODO: 确认这个消融实验是否已经完成]`
- `[TODO: 决定是否主张鲁棒性，还是只主张平均性能提升]`

避免使用 `[TODO: 改进]` 这类模糊 TODO。

## 更稳妥的主张方式

如果证据不完整，中文草稿中使用谨慎写法：

- “当前结果初步表明...”
- “如果补充实验成立，可以进一步主张...”
- “目前证据更适合支持较弱版本的结论...”
- “该主张需要额外 baseline 或 ablation 支撑。”

最终英文正文中，不要把谨慎说明翻译成强主张。
